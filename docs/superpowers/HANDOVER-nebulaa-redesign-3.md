## 1. What this product is
Nebulaa is one platform for small businesses (customers never see the old names Gravity, Pulsar or Orbit). This repo (`Marketing-agent---nebula`) is the **Content** app: it writes captions, makes images and videos, plans a month of posts, publishes through **Ayrshare**, and charges in **Quarks** (1 Quark = $0.02, prices all come from `backend/config/apiCosts.js`, never hard-code one). It is a **managed service**: the team's CSMs run client accounts, so staff tools matter as much as customer screens.
Other apps: Pulsar (outreach: WhatsApp, SMS, email, voice calls; separate repo `Pulsar`, brief in `docs/superpowers/BRIEF-pulsar-2.md`) and Orbit (lead generation, not started). They will join one login, one brain (shared business memory) and one Quark balance later.

## 3. Release procedure (and its traps)
- Release = build two linux/amd64 images, smoke-test the backend image, push to ECR, switch both ECS services with automatic rollback: `bash docs/superpowers/ops/release-prod.sh` (asks to type DEPLOY twice). `ENV=test` and `DRY_RUN=1` exist. `NO_CACHE=1` rebuilds from scratch (use after a disk-full or a "canvas package.json is not valid JSON" error).
- To switch to images already pushed: `ENV=prod TAG=prod-<sha> bash docs/superpowers/ops/deploy-ecs-release.sh`.
- Rollback command is printed by the deploy script; ECS also rolls back by itself when a new task cannot start (this saved production once).
- **Never edit `release-prod.sh` while it is running** (bash reads scripts as it goes; a run died at "line 63 syntax error" after pushing images).
- **Disk:** Docker used to fill the owner's Mac (every release image kept locally). `docs/superpowers/ops/docker-cleanup.sh` removes old local copies (all are in ECR); run alone it asks for YES; `release-prod.sh` checks free space first (`MIN_FREE_GB`, default 6) and cleans up after itself. Product data is not on the Mac.
- Releases cost nothing meaningful (about $2 a month of ECR storage in total) but each is the owner's time: **batch fixes and ask for one release**, unless a customer-facing break. An ECR lifecycle policy (keep the newest 15 tagged images, delete untagged after 1 day) was offered and NOT yet set; there is none today (about 22 GB stored).
- Local preview with sample data (never a real account): preview entry `onboarding-preview` in the parent folder's `.claude/launch.json` runs `vite --config scripts/visual-audit/vite.audit.config.mjs` in `frontend/` on 127.0.0.1:3100 with the fake API in `frontend/scripts/visual-audit/mock-session.js`. Changing only the `#/` part of the address does NOT reload the page (so old mock data stays); run `location.reload()` after editing the mock.

## 6. How the main pieces work (new this session)
- **Staff roles** (`backend/services/staff/`): `permissions.js` is the single permission table (Owner, Admin, CSM; spec in `docs/superpowers/specs/2026-10-07-admin-console-design.md`); `roles.js` (only Owner manages Admins/Owners, last Owner protected, first-Owner bootstrap), `activityLog.js` (+ `models/StaffAction.js`), `middleware/requireStaff.js`, router `routes/staff.js` mounted at `/api/staff`. `User.staffRole` ('owner'|'admin'|'csm'|null); `isCsm` kept in sync for CSMs; staff accounts are `isHidden`. `services/csmAccess.js`: acting tokens (8 h, re-checked on every request in `middleware/auth.js`; payments, password change, account deletion and `/api/csm` refused while acting); the "Staff area" menu item and `/staff/*` routes (`frontend/pages/staff/`).
- **Client list/page**: definitions live in `services/staff/clientStatus.js`: active = signed in or used a feature in 7 days; paying = a `paid` payment record or an active `plan.subscriptions` entry; trial = not paying and `trial.isExpired` false; attention reasons (Quarks under 100, drafts waiting over 3 days, inactive over 7 days, onboarding unfinished, no social account, failed post in 7 days). The list loads all visible customers and filters in memory (fine for thousands; revisit past ~10,000). Accounts without `plan.tier` resolve to `managed` (everything included).
- **Home numbers** (`services/staff/home.js`, `health.js`): health cards come from `services/opsAlerts.js` `snapshot()` (in memory since the last server restart, one task) plus the Ayrshare breaker; growth uses IST day boundaries; `GET /api/staff/home`. The screen that shows it is not built.
- **Failure alerts** (`services/opsAlerts.js`): emails after 3 failures in 10 minutes, one per category per hour; categories image, publish, social_connect, payment, ai_text, video, hero_video. Needs `ALERT_EMAILS`.
- **Server-side media**: `POST /api/video-generation/renderMissing {jobId, kind:'images'|'clips'}` queues a job that renders only missing scenes by calling the same handlers as the per-scene buttons (money rules unchanged: charge per scene just before it renders, refund on failure). The single-scene routes now refuse to redo an existing image/clip unless `force: true` (stops silent re-spend). Queue recovery no longer hands out a fixed refund for jobs flagged `perSceneCharging`.
- **Video publishing**: `schedulePost` now really posts through `services/videoPublish.js` (Ayrshare, now or with `scheduleDate`); previously it only recorded a status nothing read. Videos cannot go to Google Business. NEVER tested against a real post.
- **Platforms**: one list `frontend/utils/platforms.ts`, icons `components/PlatformIcon.tsx`, icon row with hover text `components/PlatformPicker.tsx`; `x` and `twitter` both mean X (server maps to `twitter`); Google Business key is `gmb`. Connect flow is the generic `/api/social/:platform/auth` (Ayrshare SSO); `gmb` was removed from `disableSocial` and added to the status route.
- **Business name**: `businessProfile.name` wins over `companyName` everywhere; saving the profile copies it to `companyName` (`services/accountNames.js`). Blueprint form pre-fills from the profile (`prefillFromProfile`).
- **Provider errors** never reach customers (`services/providerErrors.js`, `frontend/utils/errors.ts`).
- Settings typing bug cause: a component declared inside render. The route-order test (`tests/routeOrder.test.js`) guards the "limiter used before it is declared" startup crash that broke one release.
