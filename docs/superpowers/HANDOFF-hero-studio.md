Branch: `dev-dk`. Written 2026-10-03 by the session that built Tasks 1-4. Read this file first, then the two docs under "Read next".

## What this feature is

Gravity gets a second video path next to the Kling reel wizard: a **Hero video** — one 15 s, 720p Seedance 2.0 clip (via fal.ai) with native music/dialogue, limited to **2 per client per month**, priced at **729 Quarks** (derived in `backend/config/apiCosts.js`, never hardcoded). It is being rebuilt as **Hero Studio**: instead of branching straight off the concept, it takes the wizard's own story (script/scenes), cast (character portraits), environment photos and the client's brand (logo, product, colours, ideal customer) and sends them to the video model as up to 9 tagged reference images, then finishes the clip (realism grade, logo mark, fades, CTA end card, loudness) on the server.

The first live runs proved the plumbing: a cinematic clip (flat, silent, no story — the reason for the rebuild) and a hand-written UGC-style clip (very believable). The rebuild goal is to make every clip as good as the UGC one, from the client's real world.

## Hard rules and gotchas learned the hard way

- **Money**: every real fal generation costs about **US$4.55** (0.3034/s x 15 s) plus 729 Quarks on the account. Never trigger one (UI Generate button, scripts, curl) without the owner's explicit OK for that specific run. Tests use fakes; no task in the plan calls fal.
- **Do not probe fal with an "invalid" submit.** Seedance accepts a submit with an empty prompt and fails it asynchronously (free, but you cannot know that in advance). Use fal's request history page to inspect.
- fal's `duration` must be a **string** `'4'..'15'`; output at `video.url`; the reference-to-video endpoint takes `image_urls` (<= 9). `@imageN` tag handling in the prompt is **unverified** until the first reference run — that run is the key live test (identity fidelity, logo/product appearance).
- Kling pipeline files are off limits: `videoService.js`, `routes/videoGeneration.js`, `videoGenerationQueue.js`, `models/VideoJob.js`. Do not import `videoGenerationPipeline.js` or `videoDraftStore.js` from hero code (they start timers; tests hang).
- Hero jobs live in their own collection (`HeroVideoJob` -> `hero_video_jobs`) because the Kling queue worker's startup/stale/GC/drain loops operate on every `VideoJob` document and would fail, refund and delete hero jobs. Keep it that way.
- Money path (do not change lightly): quota check -> deduct (729) -> create job -> oldest-wins quota recheck -> submit to fal -> poll -> complete / fail with refund-once (atomic claim). Orphaned unsubmitted jobs are failed + refunded after 10 minutes; jobs older than 60 minutes ask fal before being age-failed; polls only reconcile, never double-refund.
- Brand data (logo, colours, website, product, ideal customer) is loaded server-side by the authenticated user id, never trusted from the request. Reference URLs must be public `https` (no localhost/private ranges); the client can only select from the server-staged set.
- Integrity: generated people are never presented as real customers or reviewers; no invented results or statistics; disclose AI. The "Testimonial" style is renamed "Creator recommendation" for this reason.
- An existing Prompt Studio override of `hero_video.plan` saved against the old template will keep serving the old (flat, silent) text; consider a reset/warning when shipping Task 7/8.
- Prompt size: the planner prompt has only ~500 characters of headroom under 14,000 at maximal input; style blocks are capped at 1,200 characters (`STYLE_BLOCK_MAX`). The test in `backend/tests/heroPrompt.test.js` builds the maximal case from a raw brief; keep it passing.

## Local testing safely

- Use a **separate throwaway database**: copy the backend `.env`, change only the database name at the end of `MONGODB_URI` (e.g. `...mongodb.net/nebulaa_hero_local?...`), then run backend (`npm run dev` in `backend/`, port 5000) and frontend (`npm run dev` in `frontend/`, port 3000). Do NOT run the backend against a database other environments use: on boot it starts the video queue worker (fails and refunds in-flight Kling jobs), the campaign scheduler (publishes due scheduled posts), the calendar, notification and analytics schedulers.
- Sign up a throwaway account in the local app. To get Quarks for a test (a hero costs 729; new accounts start with ~100), use the existing admin panel at `/#/admin/login` with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` values from your own `.env` (set them locally if missing) -> open the user -> "+ Add Credits".
- Atlas must allow your IP (Network Access). fal needs `FAL_KEY` with balance; an exhausted balance returns 403 "Exhausted balance" at submit (the job is refunded automatically).
- Never commit `.env` files, keys, or the `backend/public/assets` build output.
