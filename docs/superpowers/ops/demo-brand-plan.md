# Demo account for the Nebulaa demo video: "Nilaa Botanics" (plan, 2026-10-20)

Owner's request: a FAKE account with complete data, as if a D2C company had used Nebulaa for a few months, so a demo video can show every workflow: profile, products, connected social accounts, learning, plan, calendar, posts in every state, performance, competitors, inbox, photoshoot, videos, billing. Built ONLY on the development database (`nebulaa_dev`) through a seed script that refuses any other database, in the style of `backend/scripts/seed-demo-agency.js` (create / remove, idempotent, `@example.test` email, password written only to a scratchpad file, never printed, no payment/AI/image/network call). The demo is recorded from the dev app (`http://localhost:3200`, backend on 5000), never from production.

- Palette: plum #3B1F3A, rose gold #C98B7B, cream #FBF3EA, sage #8AA17D. Fonts: a serif display with a clean sans.
- **Products (8):** Kumkumadi Glow Serum 30 ml (Rs 1,299), Saffron and Sandal Face Mask 100 g (Rs 749), Rose Petal Toner 150 ml (Rs 549), Neem and Turmeric Cleanser 120 ml (Rs 449), Bakuchi Night Repair Cream 50 g (Rs 1,099), Tinted Mineral SPF 40 50 ml (Rs 699), Coconut and Hibiscus Hair Oil 200 ml (Rs 599), Lip Balm Trio (Rs 399). Each with description, key ingredients, benefits, 2 to 3 pictures.

## Hard rules
No paid or provider call; dev database only; no real social API; no `.env` reads; fake email `demo-nilaa@example.test`; every image and video generated locally (node-canvas/sharp/ffmpeg-static) and stored where the dev app can serve it WITHOUT shipping into the production frontend image (for example a git-ignored folder served by the dev backend only when not in production, or an uploads folder the app already serves; decide in the impact map); never touch other accounts; the `remove` mode deletes exactly what `create` made; the data must pass the app's own read paths (open every screen with it).

## Build stages

- Stage 2 (content): calendar, drafts, campaigns, performance, brand memory, plan and Blueprint.

- Stage 4: walk through every screen in the browser with the demo login, fix anything empty or wrong, write the demo script (the order of screens and what to say) at `docs/superpowers/ops/demo-script.md`.

# HOW TO EXECUTE THIS PLAN (written for the next Claude account; read the whole file first)

## Facts you need (verified in this repo on 2026-10-20)
- **Pattern to copy:** `backend/scripts/seed-demo-agency.js` (create/remove, refuses any DB except `nebulaa_dev`, idempotent, `@example.test` email, password to a file with `--password-file`, never printed) and `backend/scripts/videos-ui-check.js` (a minimal verified starter user). The throwaway-user recipe that works for the app's gates: `isVerified: true`, `onboardingCompleted: true`, `plan: { tier: 'professional', addons: [...] }`, `consent: { termsVersion, privacyVersion, acceptedAt, source }` using `backend/config/legalVersions.js` (otherwise a Terms popup appears), `credits: { balance, planBalance, planExpiresAt }` for Quarks. Tokens: `require('../middleware/auth').generateToken(userId)`; `localStorage.authToken` in the browser.
- **Models that matter** (all in `backend/models/`): `User` (businessProfile, plan, credits, ayrshare, consent, tour), `BrandAsset` (logo, colours, characters, environments), `Product`, `Blueprint` (kind 'plan' for the plan runs; the designed edition lives in `designed`), `WeeklyProposal`, `ContentCalendar`, `Draft` (status values include `approved`, `scheduled`, `published`, `archived`, `binned`; `origin` manual or automation; `campaignId` link), `Campaign`, `Analytics`/`AnalyticsSnapshot`/`AIContentPerformance`/`SocialSnapshot` (performance; read `backend/services/performance/*` and `routes/analytics*` to see exactly which collection and fields the Performance page reads), `Competitor` + `CompetitorSnapshot` (12 weeks of snapshots; `services/competitors/*`), `AIBrandMemory` (`learnedItems` shape: read `backend/services/brandMemory/*` and `docs/superpowers/ops/brand-memory.md`; the simplest correct way is to build the source rows and CALL the real runner so the learned items are produced by the app's own code), `SocialInboxConversation` + `SocialInboxMessage` + `AutoReplySettings` (inbox), `PhotoshootJob`, `StudioVideo`, `QuarkLedger`, `Notification`, `ContentIdea`, `HomeDraft`.
- **Best trick:** wherever the app has a pure "compute from stored data" service (brand memory runner, performance learnings, home summary, competitor insights), seed the RAW rows and let the app compute the rest, so the demo exercises real code paths and cannot drift from the screens.
- **Images and videos, zero cost:** node-canvas (installed; fonts in `backend/assets/fonts`, see `services/studioVideoFinish.js` for how text is drawn), `sharp`, and `ffmpeg-static` (zoom/pan clips from stills, see `services/studioVideoChain.js`). Store generated files OUTSIDE the production frontend image: for example `backend/demo-assets/` (git-ignored) served by the dev backend only when `NODE_ENV !== 'production'`, with absolute `http://localhost:5000/demo-assets/...` URLs in the data. The production release script builds the frontend from `frontend/`: nothing demo may be added under `frontend/public`.
- **Connected socials without the real API:** find every read that would call Ayrshare for a connected account (`/social/status`, analytics refresh, inbox sync, profile watch `services/ayrshareProfileWatch.js`, publishing) and make sure the demo user (profile key starting `demo-`) is served from stored data only; if a path would call the provider, add a guard `if (isDemoProfile(user)) return stored` (tiny, tested, logged as a decision). Never put a real key anywhere.
- **Run the app:** backend `preview_start redesign-backend` (port 5000, dev DB); frontend `cd frontend && npx vite --port 3200 --strictPort` then `http://localhost:3200`; the owner's app on port 3000 is an OLD build, ignore it.
- **Every decision** goes in `docs/superpowers/DECISIONS-LOG-2026-10-20.md` (continue the D-numbers, now at D23) or a new dated log; every owner request in `docs/superpowers/OWNER-REQUESTS-LEDGER.md`.
