# Stage 5 real-database check (Task 8)

Script: `backend/scripts/listening-realdb-check.js` (`node scripts/listening-realdb-check.js` to run, `... cleanup` to remove leftovers of an interrupted run). Database: `nebulaa_dev` only; the script connects, refuses any other database name, and runs nothing else. Run twice back to back on 2026-10-17: 42 PASS, 0 FAIL both times, exit 0. No server was listening on 3000 or 5000 (`lsof`), and no dev server was started.

## Safety
- Throwaway accounts use the email prefix `zz.rdbchk.rdbcheck5-`; their ids are also written to a temp file as they are made, so a purged or interrupted run can still be cleaned. Lease keys start `listening_scorer_lease_rdbcheck5`; the real `listening_scorer_lease` row was read before and after and did not change (it does not exist on this database).
- The real `openAI.callTextLLM`, `spendGuard.check/record` and `opsAlerts.notify` are replaced by trip-wires; the run proves the default `callText` path hits the trip-wire, and at the end that nothing reached any of them. The model is a fake that counts calls and labels by keywords.
- Cap and pause checks use simulated clocks in June 2031 so global counts are exact. Passes are scoped to the throwaway ids.
- Console warnings from the scorer were collected and scanned: no line carried comment text.

## Defects found
1. Recent negatives on the card showed 80-character previews of private messages (DMs), against the spec's "private messages are never shown outside the Inbox" (the plan said previews are unfiltered because it is the owner's inbox, but the card sits on My plan). Fixed in `backend/routes/listening.js`: private items (stored kind or live item) are left out of `recentNegative`. Test first in `listeningRoutes.test.js`. The counts still include private messages.
2. The quote filter paid about 125 ms on its first call, about 65 ms on the second, and about 90 ms on the first Tamil/emoji text (about 270 patterns compile on first use, separately for one-byte and two-byte text). Not a bad pattern: after the warm-up every hostile 160-character string takes under 1 ms. Fixed by compiling once at load in `helpers.js`. The new timing test failed before the fix (116 ms and 87 ms) and passes after.
No index, enum, nested-key or query-shape defect was found; the Stage 5 models and queries behaved on a real database as designed.
